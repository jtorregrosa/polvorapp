# 0007. Runtime i18n: es, ca-ES-valencia, en

- Status: Accepted
- Date: 2026-09-30

## Context

The UI must support Spanish, Valencian and English (vision), switchable by the user (UC-27).
Emails are also localised. Exports keep the format and language required by each recipient.

## Decision

- Locales: `es-ES` (default), `ca-ES-valencia`, `en`.
- Frontend: **react-i18next** with runtime switching; JSON translation files per locale and
  namespace (one namespace per feature); preferred language stored on the user profile.
- Translation keys in English, namespaced per feature (`registry:arquebusier.form.nationalId`).
- Dates and numbers formatted with `Intl` / date-fns locales (`ca` for Valencian).
- Backend: validation and email texts localised via .NET resource files, driven by the user's locale.
- Domain enums are translated in the UI; stored values are always the English code terms of the glossary.
- CI check that every locale contains every key; no hard-coded user-facing strings (lint rule).

## Consequences

- One build serves all languages; no per-locale deployments.
- Valencian translations need a reviewer familiar with festival vocabulary.

## Alternatives considered

- **Compile-time i18n** (one build per locale) — requires reload to switch language; rejected.
